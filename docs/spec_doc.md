
# 一、项目概述


## 1.1 项目背景

某大型钢铁集团拥有多条热轧、冷轧自动化钢板产线，当前采用全人工目视质检模式，存在产线提速受限、质检标准不一、新缺陷响应滞后、质检数据孤岛四大核心痛点：人工仅可抽检 20% 产品，年度缺陷漏检造成客诉赔付 160 万元，产线为适配人工降速带来年产能损失 2000 万元；白夜班质检检出率差距 14%，新工艺衍生未知缺陷人工适配周期 2~4 周；纸质记录无法数字化沉淀，模型缺少训练数据无法迭代优化。为破除现有质检短板，立项研发 AI 智能表面缺陷检测系统，依托 YOLO+VLM 双视觉引擎架构，实现全流程自动化智能质检。

## 1.2 建设总体目标


### 1.2.1 业务目标

实现钢板 100% 全检，取消人工抽检模式，释放受限产能
统一缺陷判定标准，年度客诉赔偿降至低位
新缺陷落地周期由 4 周缩短至 2 天
质检数据全量数字化，打通生产-质检数据链路，反向指导生产工艺优化

### 1.2.2 技术目标

搭建分层模块化 AI 质检平台，YOLO+VLM 双引擎协同检测
配套可视化仪表盘、自然语言交互、数据自动归集能力
系统适配工厂封闭工业局域网，兼容现有工控硬件
支持后续多产线扩容扩展

## 1.3 系统技术架构

系统采用 **双前端架构**，集成 YOLOv8 目标检测模型与阿里通义千问 Qwen-VL-Max 视觉大模型，形成"YOLO 快速筛查 + VLM 精细复核"双引擎协同检测流水线。系统功能涵盖：用户登录认证、实时检测仪表盘、缺陷严重度分级、RAG 根因分析、Bad Case 自动收集、批量检测、检测历史审核、数据报表导出等核心模块。

# 二、业务需求分析


## 2.1 解决产线节拍不匹配痛点：实现高速在线全检

业务要求：匹配 1.5m/s 产线速度、30s/块钢板生产节拍，单张图片检测耗时 ≤50ms，取消因人工瓶颈导致的产线降速。当前系统已实现 YOLO 单张推理耗时 <15ms（CPU 环境），VLM 接口响应 <8s，批量检测支持多图片并发处理。

## 2.2 解决人工判定主观性痛点：统一量化质检标准

业务要求：依托 AI 算法固化缺陷判定阈值，消除白夜班检出率差值。当前系统已实现置信度阈值可配置（默认 0.01），自动输出缺陷位置、类型、置信度，并支持缺陷严重度 A/B/C/D 四级自动分级（面积权重 60% + 置信度 40%）。

## 2.3 解决新型缺陷适配缓慢痛点：零样本快速识别

业务要求：VLM 零样本大模型，新缺陷出现即刻识别。当前系统已集成 Qwen-VL-Max 视觉大模型，支持零样本缺陷描述识别，不依赖预标注样本。VLM 分析采用结构化 Prompt 工程，输出标准化 JSON 格式检测结果。

## 2.4 解决数据孤岛痛点：全链路数据数字化闭环

业务要求：废弃纸质台账，所有质检结果自动入库。当前系统已实现：检测结果自动存入 SQLite 数据库、Bad Case 低置信度样本自动收集归档、CSV/HTML 多格式报表导出、Plotly 缺陷分布饼图与趋势图可视化。

## 模块 2：产线实时智能检测模块（双引擎协同核心）


### 2.1 图像采集接入

支持用户手动上传单张/批量钢板表面图像
兼容网络共享文件夹挂载、HTTP API 两种图片上传方式
自动拉取产线实时钢板图像（预留接口）

### 2.2 双引擎智能分流检测

系统实际实现的双引擎协同检测流程如下：
YOLO 快速筛查：使用 YOLOv8 模型进行一级检测，输出缺陷包围盒、类别、置信度
VLM 精细分析：基于阿里通义千问 Qwen-VL-Max 云端 API，对图像进行二级语义级复核
置信度分流策略：高置信度（≥0.8）YOLO 直出，中置信度（0.5-0.8）VLM 复核，低置信度（<0.5）转人工审核
异常兜底：VLM 云端 API 超时/故障时系统自动降级，切换为本地图像分析（Canny 边缘 + HoughLines 纹理 + OTSU 暗区检测），保障业务不中断

### 2.3 缺陷结构化输出

自动生成含缺陷坐标 (x1, y1, x2, y2)、缺陷类别（crazing/inclusion/patches/pitted_surface/rolled-in_scale/scratches）、置信度的 JSON 数据
检测统计面板实时显示：耗时、检测引擎类型、缺陷总数、各类别分布

### 2.4 检测结果可视化

标注图像：在原始图像上绘制彩色包围盒 + 缺陷标签
中文标签映射：由于 OpenCV cv2.putText 不支持中文，系统采用英文缩写映射方案（CRACK/INCL/PATCH/PIT/SCALE/SCR），确保标注清晰
热力图：基于缺陷分布生成密度热力图，直观展示缺陷集中区域
检测报告卡片：以白色卡片形式展示每个缺陷的详细信息（类别、置信度、位置、面积）

## 模块 3：缺陷严重度分级与 KPI 监控模块（新增）


### 3.1 缺陷严重度自动分级

系统自动对检测出的每个缺陷进行 A/B/C/D 四级严重度分级：
A 级（严重）：高置信度 + 大面积缺陷，需立即停机处理
B 级（中等）：中高置信度 + 中等面积，需重点关注
C 级（轻微）：中低置信度 + 小面积，可记录跟踪
D 级（忽略）：低置信度 + 极小面积，可忽略
分级算法：综合缺陷面积占比（60% 权重）+ 检测置信度（40% 权重）加权评分。

### 3.2 KPI 实时监控面板

仪表盘首页实时展示四大核心 KPI 指标：
漏检率 KPI：目标 < 1%，实时显示当前推定漏检率
过杀率 KPI：目标 < 5%，监控误判良品比例
平均检测延迟：目标 < 50ms，监控系统实时性能
累计检测量：统计总检测次数与缺陷检出数量

### 3.3 双引擎调度状态

仪表盘展示当前双引擎协同调度策略：高置信度→YOLO直出、中置信度→VLM复核、低置信度→人工审核、Bad Case→自动收集迭代。

### 3.4 系统资源监控

# 十二、系统实现亮点与技术特色


## 12.1 双引擎协同架构

系统采用 YOLO + VLM 双引擎协同检测架构，充分发挥两种 AI 技术的互补优势。YOLO 负责毫秒级快速筛查，VLM 负责语义级精细复核，形成"快筛+精审"的高效检测流水线。

## 12.2 多层级容错降级

VLM API 超时/故障 → 自动切换 LocalAnalyzer 本地图像分析
RAG API 认证失败 → 静默跳过，仅展示本地知识库
端口占用 → 启动时自动释放冲突端口
模型加载异常 → 详细错误日志，避免进程崩溃

## 12.3 中文兼容性解决方案

针对 OpenCV cv2.putText 不支持中文字符渲染的技术限制，系统采用 CN_LABEL_MAP 英文缩写映射方案，将 6 类缺陷中文名映射为简洁英文缩写（如"裂纹"→"CRACK"），确保检测标注框文字清晰可辨。

## 12.4 一体化滚动分析面板

系统将检测报告、严重度分级、RAG 根因分析、Bad Case 收集四大分析面板整合为单个可滚动窗口（max-height: 580px, overflow-y: auto），用户通过鼠标滚轮即可一览全部分析结果，减少页面纵向长度，提升操作效率。

## 12.5 科技感深色主题 UI

系统采用自定义 CSS 深色科技风格主题，包含：网格背景纹理、辐射渐变光效、玻璃拟态（glass morphism）登录卡片、半透明蓝色滚动条、高对比度文字配色方案，白色卡片区域强制深色文字，确保所有信息清晰可读。
