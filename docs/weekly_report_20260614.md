### 1. 算法与后端开发（双引擎协同与增量学习）
* **数据飞轮闭环 (DB层)**：在 [src/db_manager.py](file:///f:/steel-defect-detection/src/db_manager.py) 中新增了 `get_audited_dataset()` 方法，用于筛选未导出的、已被人工修改确权（`review_status = 'corrected'`）的 Bad Case 数据记录，并将其格式化导出为标准 YOLO 标注格式，打通了“审核-归档-导出重训”的数据链路。
* **异步后台训练 API (服务层)**：在 [server.py](file:///f:/steel-defect-detection/server.py) 中实现并注册了两个全新接口：
  * `/api/train/start`：将修正后的 Bad Case 图像和标准 TXT 标注导出，合并至 NEU-DET 原始 1800 张图片的底库中，通过子进程（`subprocess.Popen`）执行后台重训（避免灾难性遗忘的混合训练）。
  * `/api/train/status`：动态读取重训日志，解析并返回当前的 Epoch、当前进度、mAP 指标及运行状态。
* **深度 RAG 检索增强融合 (AI层)**：在 `/api/detect` 推理流程中引入 RAG 技术。当 YOLO 检测出缺陷后，系统根据缺陷种类自动匹配本地冶金知识库（`KNOWLEDGE_BASE`）中的物理成因和改进对策，并将其动态嵌入 VLM Prompt 中，生成标准 JSON 格式的深度物理根因分析与紧急停机处置建议。

### 2. 前端大屏与人机交互更新
* **数据飞轮与模型迭代控制面板**：在 [frontend/src/App.tsx](file:///f:/steel-defect-detection/frontend/src/App.tsx) 中为 `ai_engineer` 角色新增控制台。显示当前数据库中待重训的 Bad Case 样本数量，并提供“一键启动增量训练”按钮；同时渲染实时进度条，动态呈现 Epoch 进度、Loss 曲线及 mAP 性能变化。
* **AI 工艺助理 (浮动对话框)**：在 React 前端右下角集成了一个透明玻璃态（Glassmorphism）的“AI 工艺助理”悬浮对话框，支持收起/展开，允许现场质检员与主管通过自然语言询问冶金原理或工艺建议（如：“氧化皮是怎么产生的？”、“今天划痕缺陷严重吗？”），实现自然语言故障诊断。

### 3. 测试与质量保证 (QA)

## 四、 项目潜在风险与应对方案

1. **后台增量训练时的算力争抢风险**：
   * *风险描述*：后台 YOLO 重训极其消耗显存与显卡算力，若重训时产线仍在持续检测，可能会导致检测延迟骤增，引发工控机崩溃。
   * *应对机制*：系统在重训期间已支持检测分流，自动降级至 CPU 推理（或局部降帧推理），保障实时检测流水线不中断，待训练完成后平滑替换加载新模型。
2. **云端 API 稳定性与封闭网络限制**：
   * *风险描述*：VLM (Qwen-VL-Max) 与 RAG API 依赖网络，厂区封闭工业网不稳定时接口可能失效。
   * *应对机制*：已实现**多层级容错降级**。VLM 超时自动降级至本地 `LocalAnalyzer`（Canny 纹理特征与 OTSU 灰度检测算法分析），RAG API 故障则静默跳过并使用内置的本地缺陷成因库，确保系统具备高可用性。
